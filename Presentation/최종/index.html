A08 · AI COMPANION / CONTEXT

FAIREWorldContextV1이 판단 입력을 만든다

게임 상태를 흩어진 객체가 아니라, 검증된 한 번의 Context Snapshot으로 묶습니다.

01

RUNTIME SOURCES

ThreatComponent
Perceived hostile count · selected target
WorkOrderComponent
Work type · state · target validity
InventorySubsystem
MAKO · Shared Storage snapshot
World queries
Workbench capability · nearby wood
02

BUILD BOUNDARY

FAIREWorldContextBuilder::
Build(Companion, LocationId)
  1. 01Stable ID와 Actor / World 유효성 확인
  2. 02MAKO · Storage SessionId 일치 확인
  3. 03허용 항목과 배열 상한으로 입력 제한

invalid actor/world 또는 session 불일치 → 빈 Context 반환

03

OUTPUT CONTRACT

FAIREWorldContextV1

  • LocationId현재 위치
  • Threat위협 존재 · 수 · 종류
  • NearbyResources[]주변 자원과 수량
  • AvailableWorkstations[]사용 가능한 작업대
  • CurrentWork · Inventories[]작업 상태 · 인벤토리
CONSTRAINTSASCII stable ID ≤ 128 · threat ≤ 32 · resource / workstation ≤ 8 · inventory types ≤ 16 · Mako / Storage SessionId match
IMPLEMENTATION EVIDENCEAIREWorldContextBuilder.cpp · AIREWorldContextTypes.h

A09 · AI COMPANION / LOCAL BEHAVIOR

StateTree가 우선순위를 고르고, GAS가 행동을 실행한다

감지된 상태를 로컬에서 평가하고, 선택된 행동 의도만 Gameplay Event로 넘깁니다.

01

STATE PRIORITY

  1. 01
    DisabledDead tag · ASC disabled
  2. 02
    SurvivalSurvival request
  3. 03
    CombatThreat target + policy
  4. 04
    SupportHealth · range · item valid
  5. 05
    DirectCommandCommand snapshot
  6. 06
    WorkWorkOrder snapshot
  7. 07
    Return / IdleNo higher request

ENGAGEMENT HoldFire · DefendPlayer · Aggressive

ROLE Balanced · SupportPriority

Combat + Support 동시 요청 시 SupportPriority면 Support 우선

02

RUNTIME EXECUTION

SENSEAI Perception시야 · 적대 감지
→
SELECTThreatComponent거리 · 정책 · 유효 타깃
→
CHOOSEStateTree우선순위 · 이동 Task
→
REQUESTGameplay EventAttack / Support 요청
→
EXECUTEGAS Ability검증 · Cooldown · GE
COMBATEventAttackRequestAttack Ability → 거리 / 대상 / Cooldown 재검증
SUPPORTEventSupportHealRequestHeal Ability → 체력 / 사거리 / 아이템 재검증
ON EXITtarget lost · dead · policy changeStopMovement · CancelAbility · Return / Follow

A10 · CROSS-DEVICE / OFFLINE TASK

Offline Task는 서버 상태와 UE 저장을 분리해 동기화한다

WebApp은 요청·조회만 담당하고, 보상 적용과 Claim은 UE5가 저장 성공 뒤 수행합니다.

01WEB APP요청 · 조회 경계
POST /api/v1/tasksCreateOfflineTaskRequest
GET /api/v1/tasks?save_slot_id=…상태 목록 · 필터 조회
DELETE /api/v1/tasks/{task_id}허용 상태에서 작업 취소
02BACKEND / SERVER CLOCK상태 · 진행량 권위
Pending→InProgress→Completed→Claimed

server clock → progress_quantity · result_quantity

03UE5 / AUTHORITY결과 적용 · 저장 · Claim
  1. SyncOfflineTasks()GET list · parse / validate
  2. start → completePOST /tasks/{id}/start · /complete
  3. TryApplyOfflineTaskResultInventory 원자 적용
  4. RequestInventorySaveSave 성공 확인
  5. POST claim서버 처리 종료
GUARDSX-Request-ID match · World + Inventory SessionId · SaveGame success → Claim · WebApp never mutates Inventory
IMPLEMENTATION EVIDENCEofflineTasks.ts · AIREOfflineTaskSubsystem.cpp · AIREOfflineTaskJsonAdapter.cpp
